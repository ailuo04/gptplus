# gpt++ 前端视觉改造设计规范

> 状态：待确认  
> 日期：2026-10-18  
> 范围：Electron 渲染层视觉、信息层级、交互反馈与视觉回归验证  
> 不包含：网关协议、模型注入逻辑、数据模型、IPC 契约和主进程业务行为

## 1. 结论

推荐方向是 **精密工作台（Precision Workbench）**。

它不是彻底换皮，而是把现有界面从“信息很多、每块都在发光”整理成一台安静、准确、可信的桌面控制台：结构清楚、状态明确、长时间使用不疲劳，同时保留 gpt++ 独有的“提供商 → 本地网关 → ChatGPT”连接关系。

这次改造的核心是减法：

1. 降低卡片、圆角、阴影、光晕和重复徽标的视觉噪音。
2. 建立明确的三级层级：页面任务、主内容、辅助信息。
3. 把连接关系收束成一个真正的记忆点，而不是在多个区域重复解释。
4. 统一深色与浅色主题，重点修正浅色主题的弱对比和灰白层次。
5. 用少量、有因果关系动效表达状态变化，不用零散动画制造“高级感”。

## 2. 现状诊断

### 2.1 已有基础

- 应用是四个真实工作页：提供商、模型、使用量、设置。
- 已有深色、浅色、跟随系统三种主题。
- 已有完整的状态语义：成功、警告、错误、Codex、不同 API 协议和网络模式。
- 已有自绘下拉框、日志抽屉、弹窗、Toast、空状态、提供商连接测试和模型测试。
- 现有冒烟入口可以切换视图、打开日志或表单，并用 Electron `capturePage()` 截图。
- 代码明确禁止远程资源，字体和图标均需本地化。

### 2.2 主要视觉问题

| 问题 | 当前表现 | 影响 |
|---|---|---|
| 层级重复 | 服务商数量、网关状态和注入状态同时出现在侧栏底部、状态栏、模型接线图和说明条 | 用户需要多次扫描才能判断什么最重要 |
| 卡片过度使用 | 页面区块、设置项、提供商、统计、日志和弹窗都使用相似的边框、圆角和阴影 | 所有内容看起来同等重要，眼睛没有落点 |
| 视觉参数过多 | 大量 12px 到 18px 圆角、多种光晕、渐变和阴影 | 界面更像功能演示，而不是成熟桌面工具 |
| 状态颜色过多 | 青、绿、黄、橙、红同时大面积出现 | 真正的异常不容易被看见 |
| 浅色主题层次弱 | 白卡片叠灰白背景、文字和边框对比偏低 | 清晰度明显低于深色主题 |
| 信息密度不均 | 模型页和设置页正文很长，部分元信息使用开发者式说明 | 常用操作被解释文字淹没 |
| 动效分散 | 多处悬停位移、脉动、闪烁、弹层缩放和图标弹跳 | 动效之间没有共同节奏，容易被感知为“装饰” |
| 大文件耦合 | `styles.css` 超过 2400 行，多个渲染模块超过 700 行 | 视觉改动容易影响已有交互，验证成本高 |

### 2.3 改造判断

继续增加渐变、光晕、圆角或更重的卡片不会解决根因。当前最值得投入的是视觉系统、信息层级和状态表达，而不是装饰层。

## 3. 目标与边界

### 3.1 目标

- 首屏能在一秒内回答：现在有哪些提供商和模型，网关是否在工作，ChatGPT 是否已注入。
- 常用动作保持在一个视线范围内：添加、编辑、测试、启用、注入、重启、查看异常。
- 深色与浅色主题具有相同的信息层级和相近的可读性。
- 组件状态统一：默认、悬停、按下、聚焦、禁用、加载、成功、警告、错误。
- 在 `940x620` 最小窗口、`1180x780` 默认窗口和 `1440x900` 宽窗口下不出现重叠、截断和横向破版。
- 保留本地资源、CSP 安全约定和现有键盘语义。

### 3.2 非目标

- 不新增前端框架、远程字体、CDN 或图标依赖。
- 不改变提供商、模型、网关、注入、更新和日志的业务流程。
- 不为移动端重做布局；Electron 窗口最小宽度是 `940px`。
- 不把应用改成营销落地页、展示型大屏或无意义的三栏仪表盘。
- 不进行与视觉目标无关的全量代码重构。
- 不覆盖当前工作树中用户已有的未提交修改。

## 4. 方向选择

| 方向 | 视觉特征 | 优点 | 风险 | 结论 |
|---|---|---|---|---|
| A. 安静桌面工具 | 低对比、少边框、弱品牌感 | 舒适、稳定、实现风险小 | 容易显得普通，连接关系失去辨识度 | 可作保守方案 |
| B. 精密工作台 | 清晰分区、仪器感刻度、局部冷色和暖色、单一连接主视觉 | 兼顾辨识度、效率与长期使用 | 需要严格控制颜色和装饰数量 | **推荐** |
| C. 分层仪表盘 | 更强数据感、更多图表面板和状态色 | 使用量页视觉冲击强 | 全应用容易过密，像监控大屏而非配置工具 | 不推荐 |

## 5. 视觉方向

### 5.1 概念

界面像一台可靠的本地网络控制台，而不是一块发光电路板。

结构上使用克制的细线、整齐的数值对齐和少量仪器刻度。品牌色只出现在可操作、可连接和需要关注的地方。视觉强度最高的位置只保留一个：模型页的连接轨道。

### 5.2 签名元素：连接轨道

连接轨道表达真实业务链路：

```text
[提供商 2] ───────── [本地网关 :18120] ───────── [ChatGPT 已注入 4]
 4 个模型              系统代理 · 运行中             重启后生效
```

规则：

- 只在模型页作为主视觉出现一次。
- 连接段使用极细线和小型流动高光，仅在线路真实连通时运动。
- 端点状态用文字和形状共同表达，不只依赖颜色。
- 侧栏底部和状态栏保留简短状态摘要，不再复制完整节点说明。
- 断开位置应一眼可见，并给出一个明确动作或跳转。

### 5.3 页面布局

```text
Desktop 1180x780
┌──────────────┬──────────────────────────────────────────────┐
│ Brand        │ Page title                         Actions   │
│ Navigation   ├──────────────────────────────────────────────┤
│              │ Primary content                              │
│              │                                              │
│              │                                              │
│              │                                              │
│ Status       │ Compact status summary                       │
├──────────────┴──────────────────────────────────────────────┤
│ Thin footer: topology summary · theme · version · logs      │
└─────────────────────────────────────────────────────────────┘

Models page
┌─────────────────────────────────────────────────────────────┐
│ Connectivity rail: provider -> gateway -> ChatGPT           │
├─────────────────────────────────────────────────────────────┤
│ Default model: selector + current slug                      │
├─────────────────────────────────────────────────────────────┤
│ Search / filters                         Model table        │
└─────────────────────────────────────────────────────────────┘
```

页面分区优先使用整行背景、留白、细分割线和标题，不把每个设置组都做成独立卡片。卡片只用于提供商条目、模型测试结果、真正的工具面板和弹窗。

## 6. 设计系统

### 6.1 颜色

深色主题使用中性石墨底色，浅色主题使用轻微带绿的纸白底色。两种主题共享相同语义，但分别校准对比度。

| Token | 深色 | 浅色 | 用途 |
|---|---:|---:|---|
| `--ui-bg` | `#101315` | `#F4F6F3` | 应用底色 |
| `--ui-surface` | `#171B1D` | `#FFFFFF` | 主要表面 |
| `--ui-text` | `#EEF2EF` | `#172127` | 主文字 |
| `--ui-muted` | `#9BA6A7` | `#596970` | 次要文字 |
| `--ui-cyan` | `#63BBC8` | `#227383` | 交互、健康连接 |
| `--ui-amber` | `#E0A34C` | `#A96417` | 需要关注、ChatGPT 注入 |

补充规则：

- 绿色只表示成功或运行，不再用于所有“已启用”。
- 红色只用于错误和危险动作。
- 黄色与橙色分开：黄色表示需要注意，橙色表示 ChatGPT/Codex 一侧。
- 大面积背景不使用高饱和色，不增加装饰性渐变球或光斑。
- 浅色主题的正文对比度目标不低于 4.5:1，次要正文不低于 3:1。

### 6.2 字体与排版

- 展示字体：`Segoe UI Variable Display`，用于页面标题和少量关键数值。
- 正文字体：`Segoe UI Variable Text`、`Microsoft YaHei UI`，用于界面和说明。
- 等宽字体：`Cascadia Mono`、`Consolas`，用于 slug、端口、URL、路径和表格数值。
- 不增加远程字体，不依赖新的字体下载。

建议字号：

| 角色 | 大小 | 字重 |
|---|---:|---:|
| 页面标题 | `24px` | 650 |
| 区块标题 | `15px` | 650 |
| 正文 | `13px` | 400/550 |
| 辅助文字 | `12px` | 400 |
| 表格元信息 | `11.5px` | 400/600 |
| 大写标签 | `10.5px` | 600，字距 `0.06em` |

限制：

- 页面标题最多比正文大一级，不使用夸张展示字。
- 所有常规文字保持 `letter-spacing: 0`。
- 短标签可以用大写和字距作为结构提示，但不要全页滥用。
- 数字列使用 tabular numerals，保证扫描时纵向对齐。

### 6.3 间距、圆角和层级

- 间距标尺：`4 / 8 / 12 / 16 / 24 / 32px`。
- 页面左右内边距：默认 `24px`，最小宽度时 `16px`。
- 卡片圆角：`8px` 上限。
- 按钮和输入框：`6px`。
- 弹窗和大型覆盖层：`10px` 到 `12px`。
- 小徽标可以使用 pill，但正文容器不使用 pill。
- 主要依靠边框和底色建立层级；阴影只用于浮层、Toast、弹窗和日志抽屉。
- 可交互卡片悬停时不整体上浮，只改变边框、背景和必要的前景颜色。

### 6.4 图标

- 继续使用现有静态 SVG 图标集，保持本地化和 CSP 兼容。
- 图标尺寸以 `14px` 为主，导航 `16px`，空状态 `22px`。
- 图标按钮必须有 `title` 和 `aria-label`。
- 同一动作在四个页面保持同一图标和文案。
- 删除纯装饰性的重复图标，避免每张卡片都带一个图标。

### 6.5 文案

- 页面副标题只解释任务结果，不复述实现机制。
- 技术说明放在标题旁的帮助提示、表格表头或必要的 inline hint 中。
- 常见操作使用动词开头：添加提供商、测试连接、设为默认、保存设置。
- 同一个动作从按钮到 Toast 使用相同词汇。
- 错误文案说明发生了什么以及下一步动作，不使用泛化的“操作失败”。

## 7. 页面改造要点

### 7.1 应用外壳

- 侧栏宽度保持约 `216px`，减少底部多个独立白框，形成简洁的底部工具区。
- 导航选中态使用一条细边和轻底色，不使用发光图标和独立滑块阴影组合。
- 顶部标题栏降低背景渐变强度，动作按钮与标题在同一基线上。
- 状态栏只保留拓扑摘要、主题、版本和日志入口，不再重复详细状态说明。
- 品牌图继续使用现有本地图标，但缩小外发光和状态点尺寸。

### 7.2 提供商页

- 页面首屏先显示提供商列表和一个紧凑摘要，不先展示多块说明。
- 提供商条目改为更规整的列表卡或两列网格，减少标签数量。
- 每个条目只保留四项核心信息：名称、Base URL、协议、模型数。
- API Key 状态放在次要信息区，默认打码，保留显示和复制动作。
- 测试连接结果就近显示在该提供商底部，不进入全页通知。
- 主操作为“添加提供商”，删除动作收纳为危险图标或更多菜单。
- 空状态只解释下一步，不把整段实现说明放在页面中央。

### 7.3 模型页

- 连接轨道是页面唯一强视觉元素。
- 默认模型选择器控制在单行，slug 用等宽字体作为辅助信息。
- 注入成功提示合并到连接轨道末端和状态栏，不再额外占一条大横幅。
- 模型表优先显示显示名、提供商、状态和默认；slug 可以在宽窗口显示，在窄窗口收进可复制的次级行。
- 排序把手、开关和默认动作保持固定宽度，避免动态内容改变行布局。
- 停用模型必须以文字和低透明度共同表达，不能只降低整行透明度导致不可读。

### 7.4 使用量页

- 顶部时间范围和显示条数控件压缩为一行工具栏。
- 统计卡数量不超过五张，使用统一的高度、数值基线和单一语义色条。
- 热力图是主图表，占主要视觉面积。
- 按模型、按提供商和请求记录使用统一表头和数值对齐。
- 请求记录在窄窗口允许横向滚动，不压缩到内容互相遮挡。
- 空数据状态保留图表框架和清晰说明，不显示空动画或无意义的占位柱。

### 7.5 设置页

- 按任务分为四组：软件更新、模型上下文、本地网关、注入与路径。
- 每个分组使用一个区块标题和行式设置，不再为每条设置在卡片内部再套卡片。
- 表单控件右对齐，说明文字控制在一到两行。
- 保存动作紧跟修改区域，并明确显示未保存、保存中、已保存和需重启状态。
- 危险动作与普通设置保持距离，使用红色只在确认阶段出现。

### 7.6 浮层、日志和反馈

- 弹窗使用更紧凑的头部、固定底栏和清晰分区。
- 日志抽屉降低行高和空白，保留级别色条，正文保持中性色。
- Toast 只显示一个主动作，位置不遮挡底栏控件。
- 加载状态使用骨架或固定尺寸占位，避免首次加载造成布局跳动。
- 空状态使用简洁图形、单句说明和一到两个动作。

## 8. 动效规则

### 8.1 节奏

- 微交互：`120ms`。
- 页面和局部出现：`160ms` 到 `200ms`。
- 弹窗和抽屉：`220ms` 到 `280ms`。
- 统一使用 ease-out；不使用回弹曲线表现普通工具操作。

### 8.2 允许的动效

- 连接轨道上线时，连接段播放一次短高光。
- 页面切换只做一次 `opacity` 和 `translateY(4px)` 入场。
- 弹窗和下拉框只做淡入与轻微位移动画。
- 日志新行可以使用一次极短淡入。
- 状态变化可以通过边框和文字颜色过渡。

### 8.3 禁止的动效

- 所有卡片悬停上浮。
- 持续脉动状态点。
- 图标旋转、弹跳或无因果闪烁。
- 同一页面多个元素同时连续发光。
- 动画宽度、高度、padding 或大范围阴影。
- 在 `prefers-reduced-motion: reduce` 下仍保留持续运动。

## 9. 可访问性与响应式

### 9.1 可访问性

- 所有主要操作可通过键盘完成。
- 聚焦环清晰可见，不能被卡片 overflow 截断。
- 开关使用 `role=switch` 和 `aria-checked`。
- 选择器保留 combobox/listbox 语义和方向键行为。
- 状态不能只靠颜色区分，必须同时有文字、图标或形状。
- 图标按钮有可读标签。
- 弹窗打开后焦点进入弹窗，关闭后回到触发元素。
- 减少动效偏好下，停止电流、脉动和长过渡。

### 9.2 窗口适配

| 视口 | 验收重点 |
|---|---|
| `940x620` | 最小可用，不破版，主要动作可见，表单可滚动 |
| `1180x780` | 默认体验，信息密度和留白平衡 |
| `1440x900` | 宽屏体验，内容有最大宽度，不无限拉伸 |

桌面端不新增移动布局。若以后把渲染层复用到普通 Web，需要另立响应式设计任务。

## 10. 验收标准

视觉改造完成后必须同时满足：

1. 四个页面在深色和浅色主题下均有真实 Electron 截图。
2. `1180x780` 与 `940x620` 下没有文字重叠、按钮溢出、水平破版或关键动作不可达。
3. 提供商添加/编辑、连接测试、模型启用、默认模型、注入开关、网关设置、日志抽屉和设置弹窗均可正常操作。
4. 主要页面只保留一个强视觉焦点；模型页的强焦点必须是连接轨道。
5. 页面中不再出现三重以上的同一状态重复说明。
6. 卡片圆角不超过 `8px`，阴影只出现在浮层和确实需要抬升的工具面板。
7. 浅色主题下正文、次要文字和禁用态可读，不使用低于目标对比度的浅灰文字。
8. `npm test` 全部通过。
9. 新视觉审计命令通过，且生成的截图不是空白页、黑屏或错误页。
10. 没有新增远程资源、网络字体、CDN、未经约束的 `innerHTML` 或明文 API Key 展示。

## 11. 风险与控制

| 风险 | 控制方式 |
|---|---|
| 已有未提交修改被覆盖 | 每个任务先看 `git diff`，只改目标段落，不整文件替换 |
| 视觉变量影响隐藏状态 | 保留语义变量，新增 token 时先映射，再逐页替换 |
| 大 CSS 文件级联冲突 | 按页面分批修改，每批都跑截图和现状测试 |
| 测试固化了旧布局 | 只更新因设计目标变化的断言，不删除测试或降低安全要求 |
| 浅色主题最后才发现问题 | 每个任务同时检查深色和浅色，不把浅色留到最后 |
| 动效拖慢低频设备 | 只动画 transform 和 opacity，支持 reduced motion |
| 视觉增强变成功能改动 | 所有数据与 IPC 契约保持不变，页面 DOM 修改仅限展示结构 |

## 12. 推荐执行顺序
