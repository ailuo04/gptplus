# 中转站余额插件设计（2026-11-06）

## 目标与范围

在 gpt++ 现有插件市场新增独立内置插件「中转站余额」，不合并到用量信息栏。首版适配 Sub2API 与 New API，复用已有提供商的 Base URL、API Key 和网络代理配置，不另存一份密钥。

用户已经选定 A 方案：ChatGPT 左侧栏底部、「设置」入口紧上方显示圆环，中心是具体剩余额度而不是百分比。切换模型后，必须跟随当前模型所用提供商切换，不能继续展示上一家余额。

本设计整合用户已确认的方向和最后补充的交互约定，整体审阅后进入实现。

## 圆环与模型跟随

- 页面当前选择的模型是余额归属依据；通过模型目录与现有路由把模型 slug 解析到稳定 providerId，不能仅按可能重名的模型标签推断。圆环可在 ChatGPT visualViewport 内自由拖动，保存位置，双击恢复默认；拖动时提示与详情同步重新定位。
- 选择切换时立即切换归属：有该提供商缓存则显示并标明更新时间，同时刷新；无缓存则显示加载状态。不得等发送下一条消息才切换，也不得使用全局最近一次请求作为另一个会话的当前模型。
- 当前模型未关联中转站、未配置对应余额适配类型、模型识别失败时，圆环中心显示红色感叹号 `!`。悬停和可访问名称说明具体原因；不显示旧提供商金额，不触发猜测性的上游查询。
- 正常状态显示具体额度，货币标识沿用上游明确的币种，不把 USD 误标成 CNY。不限额显示「不限额」，空间不足时圆环内使用 `∞`，完整含义在悬停和详情中展示。
- 圆环按剩余比例绘制。能读取到可信累计消耗值时，百分比为 `1 - 消耗值 / (消耗值 + 余额)`；20% 及以上为绿色，低于 20% 为黄色，低于 5% 为红色。无法取得累计消耗值时不绘制虚构进度。金额超过圆环容纳宽度时缩短展示，详情和可访问文本保留完整值。
- 余额数字采用用户选择的第二种动效（逐位滚动）：只有本次数值改变的数位滚动，没变化的数位、货币符号、小数点和分组符号保持静止。示例 `72.40 -> 71.92` 中十位 `7` 不滚动，仅个位 `2 -> 1`、十分位 `4 -> 9`、百分位 `0 -> 2` 滚动约 400ms。
- 比较已经按同一格式展示的前后金额，按整数/小数数位对齐，使用等宽数字避免横向抖动。金额不变不播放动画；首次显示金额、切换为感叹号/不限额等非金额状态时直接更新。整数进位或位数减少时，仅新增、移除和改变的数位作过渡，不把同一数位的未变化数字一起滚动。
- 每次刷新只滚动一次，不循环播放，不把整个金额从零计数到目标值。新结果到来时结束前一过渡并呈现最新目标，不能排队播放过期余额。动画只影响显示，不参与余额或消费差值计算；启用 `prefers-reduced-motion` 时省略滚动并直接显示最新数值。
- 鼠标悬浮圆环时弹出详情，移开时收起，展示当前中转站名、余额、累计消耗值、最近一次消耗量、单位、上次成功刷新时间、错误状态和手动刷新入口。展开时可查询其他已配置提供商；不持续轮询未被选中的所有提供商。
- 读取失败时显示红色错误标记，详情保留上次成功数据及其时间并明确标记过期；失败不能表示成余额为零。

## 配置、刷新与生命周期

- 插件默认未安装、未启用。插件设置选择已有提供商并分别指定 `sub2api` 或 `newapi`；未配置类型的提供商不查询。
- 自动刷新间隔可自定义，默认 60 秒。使用秒为单位的数值输入，允许 10 秒至 86400 秒的整数，非法输入提示错误而不是悄悄改值。保存后立即应用，无需重启 ChatGPT。
- 启用、选择新的提供商、用户手动刷新、定时刷新均走同一查询执行器。同一提供商正在进行的请求复用，避免定时与手动请求重叠。
- 同一提供商内部切换模型只改变当前模型标识，不清空其额度基线；切换到其他提供商后使用该提供商自己的缓存和基线。
- 单个请求具有超时与响应大小限制；限流时遵守 Retry-After，界面显示暂缓状态，不高频重试。
- 老提供商的晚到响应可以更新它自己的缓存，但不能覆盖当前圆环或弹出冒充当前上游的提示。
- 页面重载、会话切换和导航后恢复挂载，不重复添加圆环或监听器。停用、卸载、应用退出时取消调度和请求，移除本插件节点与注册脚本，不影响其他插件。
- 复用项目现有 CDP 通信能力，但余额插件不依赖用量信息栏是否启用；只启用余额插件时也能建立所需页面桥接。

## 查询不消耗模型 Token

- 仅调用站点的只读额度/用量接口。Sub2API 使用 `GET /v1/usage`；New API 使用 `GET /api/usage/token`，币种和额度换算在需要时读取站点公开配置。
- 余额刷新、配置验证、模型识别、计算消费和绘制提示均由本地确定性代码执行。不调用模型聊天、Responses、Messages、图片或语音生成接口，不发送测试对话，不借助模型解释账单。
- 官方这两种查询处理器读取已有额度与用量数据，不发起模型生成，因此该查询链路不产生模型输入/输出 Token。插件不能承诺第三方站点自行修改后的额外收费或限流政策。
- New API 的原始 quota 数值必须根据明确的站点换算比例处理；无法确定比例时显示「额度」及对应原始单位，不假装是已换算金额。
- Sub2API 需区分 Key 总额限制、钱包余额和订阅周期额度。订阅额度明确标注其性质；若接口无法给出完整可用额度约束，在详情中说明，不把部分额度伪称为账户总余额。

## 每次刷新期间的消费提示

- 当前选中提供商每次网络刷新成功且可计算区间消耗后，在圆环上方显示一个非模态浮动提示：默认按圆心水平居中；提示节点挂在页面根级 overlay 层、不嵌套在窄侧栏或其 overflow 裁剪容器内，并使用 viewport 定位；依据圆环可视矩形计算位置，靠近 ChatGPT 窗口边缘时向内平移，整个金额、负号、提示背景均须保持在 visualViewport 内且四边至少相距 8px，不能以裁剪、隐藏负号或缩短金额处理边界问题；侧栏滚动、布局变化、拖动、窗口或 visualViewport 尺寸变化时重新定位；可见内容仅为红色负数金额，例如 `-$0.0234` 或 `-¥0.0234`，不显示说明文字、提供商名或时间间隔。提示淡入显现、停留约 2 秒、再淡出消隐并移除；不抢焦点、不弹操作系统通知、不发声音。定时和手动刷新均显示；仅重绘缓存时不重复显示。若停留期间出现新的成功刷新，则用最新金额替换并重新计时，不堆叠多条提示。尊重 `prefers-reduced-motion`，减少动态效果时省略渐变动画但仍短暂显示并自动消失。
- 浮动提示示例为 `-$0.0234`，不附带文字；两次成功快照的真实间隔放在详情中，失败恢复后不得仍固定写成「过去 1 分钟」。成功比较得到零消费时仍显示红色 `-$0` 金额。
- 优先比较相同提供商、相同凭据、相同单位和相同统计口径的累计已扣额度。New API 使用 `total_used`；Sub2API 使用相应 Key 的累计用量/实际扣费字段，不把余额变化直接等同于精确消费。
- 如果站点只有余额而没有可比较的累计已用字段，在详情中明确标注「余额净减少」，不称为精确消费；充值与消费同时发生时不尝试从净余额倒推出真实花费。余额增加时不弹出负数，在详情中显示「余额增加，消费无法单凭余额确定」。
- 首次成功读取建立基线，详情显示「余额已更新，消费统计从本次开始」，此时不弹消费金额，不伪造历史消耗；请求失败只在圆环和详情标明刷新失败，不更新成功基线。下次成功比较覆盖自上次成功以来的实际时段。
- 累计数回退、统计周期重置、币种或单位变化、站点类型变化、Base URL 或 Key 更换时重建基线并在详情显示「统计口径已变化，本次不计算」，不弹消费金额，不能弹出负消费。
- 每个提供商/凭据独立保存内存中的快照与基线。切换提供商不会把 A 的余额减去 B 的余额；应用重启后重新建立基线，不新增持久账本。
- 这里统计的是该 API Key 的区间整体用量，可能包含它被其他客户端或会话使用产生的消耗，不宣称仅属于当前模型或当前对话。
- 计算使用未格式化数值，展示时才舍入。消费金额保留比余额更多的小数位；非零微小消耗不得四舍五入成误导性的零。

## 组件与数据流

1. plugin-manager 注册插件并规范化 providerId 到适配类型的映射及 refreshIntervalSeconds；renderer 的插件配置表单负责展示、校验与保存。
2. 独立余额客户端实现两种站点的固定只读路由、认证、单位解析和错误分类，沿用项目的系统代理与凭据读取方式。
3. 独立余额运行时负责当前提供商、内存快照、消费差值、刷新调度、请求合并、基线失效和插件启停。
4. ChatGPT 页面脚本负责挂载圆环与详情、读取当前模型标识、呈现快照和短暂提示；主进程通过现有 CDP 能力传递脱敏配置与展示数据。
5. 页面选择变化 -> 本地路由解析 providerId -> 余额运行时选择对应缓存并刷新 -> GET 查询 -> 归一化结果与同一身份的快照比较 -> 仅向仍匹配的页面展示。

页面桥接仅传模型/提供商标识、名称、余额、单位、时刻、状态与提示。上游 API Key、鉴权头和完整原始响应不进入 ChatGPT 页面、注入脚本或诊断日志。

## 实现约束

不新增依赖，不提交或推送，不改无关模块或现有全局配置。不访问真实密钥或发真实付费请求来验证。保留提供商卡片原有 API Key 复制入口，不修改既有用户未跟踪文件。只在用户实际启用插件时启动其运行时，停用后不继续访问上游。

## 验证与验收

- 使用隔离、明确标注的合成账务夹具和本地 HTTP 服务验证 Sub2API 的钱包/限额/订阅模式、New API 的剩余/累计已用/不限额/单位换算。
- 请求记录断言只出现允许的 GET 查询且不含对话请求体；验证配置和手动/定时刷新均不调用任何模型生成路由。
- 覆盖默认 60 秒、自定义间隔保存与即时生效、请求合并、限流、超时、停用取消、晚到结果隔离；模拟窗口左右边缘、窄 viewport 与长金额，确认 overlay 不被侧栏裁剪且完整落在可视窗口内。
- 覆盖同提供商切换模型、跨提供商切换、同名模型不同提供商、未关联模型红色 `!`、页面导航/重载后恢复且不重复挂载。
- 验证数字滚动只作用于变化位：部分数位变化、仅最后一位变化、金额完全不变、整数进位/位数减少、零值、币种与非金额状态切换、快速连续更新，以及 reduced-motion；断言未变化位没有动画、最终金额准确且不重复播放。
- 覆盖首次建立基线、零消费、微小消费、充值/余额净变化、累计回退和周期重置、失败后较长真实间隔、Key/地址/单位改变、跨提供商不交叉相减、每次成功刷新仅提示一次。
- 覆盖正常/加载/未知/失败/过期/不限额状态的文案和可访问性；测试消费提示仅显示红色负数金额、挂在页面根级 overlay 而非侧栏裁剪容器、位于圆环上方且优先居中、靠边时自动向内避让、负号与长金额完整可见、窗口大小与金额改变后重新定位、淡入/停留 2 秒/淡出、reduced-motion 行为及重复刷新时替换不堆叠；测试页面脚本与公开 IPC 数据不含密钥。
- 覆盖可信累计消耗值、缺失消耗值、20% 与 5% 精确边界、三级颜色、悬浮弹出与移开收起、圆环到详情之间移入不移除、详情四边避让、拖动四边限制，以及长负数提示在左上/右上角仍完整位于 viewport 内。
- 按项目约定执行相关单测、完整 npm test、语法检查和隔离 Electron 界面冒烟。真实 ChatGPT 当前版本的模型识别与挂载未实测时明确报告，不能把静态测试说成真实客户端验证。
