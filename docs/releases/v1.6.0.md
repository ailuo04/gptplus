# gpt++ v1.6.0

## 更新内容

### 新增：最近请求显示真实思考强度

- 主页「最近请求」现在会在渠道名后显示本次请求实际发给上游的思考强度，例如 `dp · 思考 高`。
- 档位来源不是 ChatGPT 请求里的原值，而是适配器最终构建出的上游请求字段：OpenAI 读取 `reasoning_effort`，Anthropic 读取 `output_config.effort`，Responses 透传读取原样转发的 `reasoning.effort`。
- Anthropic/DeepSeek 的档位映射会按实际上游值显示，例如客户端请求 `medium`、上游收到 `high` 时显示「高」；鼠标悬停可看到「ChatGPT 请求：中」。
- 请求没有携带显式档位时显示「思考 默认」，由上游使用默认值；升级前的旧记录没有档位字段，不会猜测补值。

### 改进：生成速度与请求收尾

- 生成速度改为「整轮输出 Token / 首个输出片段之后的耗时」，思考阶段计入分母；首个输出片段包括思考、正文和工具参数，速度不再因长思考而虚高。
- 流式上游发出 `response.completed` / `response.failed` 等终点事件后立即停止继续读取，并修复客户端收到终点后正常关闭连接被误记为 HTTP 499 的问题。
- 同步更新用量信息栏和插件说明中的速度口径。

## 兼容性

- 提供商、API Key、注入状态、用量历史和插件配置无需迁移。
- 思考强度只影响新产生的请求记录；历史记录保持原样。
- Responses 到 Responses 的透传行为不变，仍按原字节转发请求与响应。
