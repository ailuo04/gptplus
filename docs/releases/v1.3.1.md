# gpt++ v1.3.1

## 更新内容

### 改进：主页「需要重启」提示条改用红色阻断态

首屏那条「配置已修改，需要重启 ChatGPT 客户端后生效」原本是琥珀色，和「还没有提供商」「网关未启用」这类普通提醒同一个视觉档位。但它其实不是提醒，而是**阻断**：配置已经落盘，ChatGPT 却仍在跑旧清单，用户不做任何操作，功能就是不对的。两种含义共用一个颜色，等于让真正要紧的那条失去分量。

现在按语义分档：

- **普通提醒保持琥珀色**：添加提供商、启用网关、启用模型、注入模型这些「下一步」，仍然是原来的琥珀底 + 左侧强调边。
- **待重启单独变成红色阻断态**：整条红底、红描边、红色左侧强调边，提示文字与警示图标同步转红；按钮从琥珀描边样式改成**实心红底白字**，和左侧栏已有的红色「重启 ChatGPT」按钮视觉统一。
- **无障碍语义一并升级**：待重启提示条的角色从 `note` 改为 `alert`，读屏软件会立即播报，而不是当成一条普通附注。

两种主题各有独立令牌（`--notice-err-bg` / `--notice-err-line` / `--notice-err-text` / `--notice-err-edge` / `--notice-err-action-*`），没有复用深色主题的红色，避免浅色底上发灰。实测对比度：浅色主题文字 6.59:1、按钮 6.47:1，深色主题文字 9.13:1、按钮 6.47:1，均远高于 4.5:1 门槛。提示条的几何尺寸（内边距、行高、圆角）完全不变，首屏不会被撑高。

### 改进：启动时立即检查更新，不再等 8 秒

原来窗口和托盘创建完成后，要 `setTimeout` 等 8 秒才发出第一次更新检查。这意味着刚开机打开 gpt++ 时，用户要在前 8 秒里面对一个「有没有新版本」还未知的界面，左栏的更新入口也处于「检查更新」的中性态。

现在启动即检测：

- **窗口与托盘创建完成后立刻调用** `updater.checkForUpdates()`。这是纯异步网络请求，不阻塞首屏渲染，也不会拖慢网关自启。
- **早到的结果不会丢**：如果检测结果在页面加载完成之前就广播出去，渲染层在 `boot()` 里会主动通过 `getUpdateState()` 补读主进程状态，所以即使错过广播，更新提示依然会出现。
- **行为仍然克制**：发现新版本只弹窗提示，不会自动下载；下载与安装依旧需要用户明确点击。

## 验证

- 全量 Node 测试：246 项、0 项失败、1 项跳过（跳过项为真实 `config.toml` 处于注入状态的用例）。
- 新增用例：主进程启动块必须直接调用 `checkForUpdates` 且不得包含 `setTimeout`，防止以后又被人为加回延迟。
- 更新既有用例：主页待重启提示条现在断言红色阻断态（`is-blocking`、`role="alert"`、按钮 `btn-danger`）与双主题的红色令牌，原先断言的琥珀色按钮样式同步改为断言普通提醒仍是琥珀色。
- 真实渲染层验证（`tools/verify-hero-next.cjs`，双主题）：提示条尺寸、文字与按钮对比度、阻断态类名与 `alert` 角色、两段式确认只触发一次重启、重启成功后提示条消失、重启失败后提示条保留且按钮可再次点击。
- 修复该验证脚本自身的一个取色缺陷：高分屏（缩放 1.25）下 `capturePage` 返回物理像素，而脚本按 DIP 坐标取样，采样框会偏出按钮、误报对比度仅 1.26:1。现在按实际缩放比换算，结果与肉眼截图像素一致。

## 安装与升级

- Release 提供 Windows x64 NSIS 安装器、差分更新 blockmap 和自动更新元数据 `latest.yml`。
- 沿用仓库现有未签名构建流程，Windows 可能显示"未知发布者"或 SmartScreen 提示。
- 升级不清空用户配置、提供商、API Key 或历史使用量数据。
- 本次起，已安装的 gpt++ 会在启动的同时检查 GitHub Release（此前为启动约 8 秒后），发现新版本仅弹窗提示，不会自动下载。
