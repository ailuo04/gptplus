# gpt++ v1.6.8

## 软件内更新摘要

- 修复部分推理模型在“测试连接”中被误判为不可用的问题。
- 模型测试改用合理的输出上限，`fapi` 等要求最小输出的上游可以正常返回结果。
- 新增针对极小输出上限导致 HTTP 400 的回归测试。

## 更新内容

### 修复：模型测试误判

- 模型测试请求不再把 `max_output_tokens` 固定为 `1`，避免推理模型因无法生成最小结果而直接返回 400。
- 测试输出上限调整为 `64`，仍只发送一次极短生成请求，同时兼容要求更高最小输出的 Responses 上游。
- 提供商卡片现在能根据真实模型响应判断是否可用，不再把可正常对话的模型显示为 `0/N 通过`。

## 兼容性

- 提供商、API Key、模型、注入状态、用量历史和插件配置无需迁移。
- 正常聊天请求的转发路径与协议转换逻辑不变。
- GitHub Release 继续提供 Windows x64 NSIS 安装器、差分 `blockmap` 和 `latest.yml` 更新元数据。

## 验证

- 全量 Node 测试 375 项：374 项通过，1 项按真实 Codex 配置条件跳过，0 项失败。
- 回归测试先复现旧版 `max_output_tokens: 1` 被上游拒绝的问题，修复后通过。
- 实际验证 `fapi` 在输出上限为 `16` 及以上时正常返回，旧版的 `2/4/8` 会返回 HTTP 400。
- GitHub Actions 会在推送 `v1.6.8` 标签后构建 Windows x64 未签名安装包并创建 Release。
