# gpt++ v1.3.2

## 更新内容

### 新增：主页右上角「Codex 配置」分体按钮

以前想看一眼 Codex 的配置，只能去「快捷入口」卡片里点「打开 Codex 配置目录」，或者自己开资源管理器找 `~/.codex`。现在主页右上角（「刷新总览」与「添加提供商」之间）多了一个分体按钮，把两种打开方式收在一处：

- **主按钮「Codex 配置」**：默认动作是在资源管理器中打开配置文件夹（`~/.codex`，支持 `$CODEX_HOME` 覆盖），一次点击直达。
- **右侧小箭头**：展开二级菜单，在「打开配置文件夹」与「打开配置文件」之间选择；后者用系统默认编辑器打开 `config.toml`。点菜单外部或按 Esc 收起。
- **视觉是一个控件**：主按钮去右圆角、箭头段去左圆角拼合成一个胶囊，悬停任意一段整块一起亮；二级菜单与按钮完全同宽、左右边缘对齐，菜单条目采用紧凑字号以适配同宽布局。

### 新增：打开 Codex 配置文件的主进程通道

- 新 IPC `gptplus:codex:open-config` 与 preload 方法 `openCodexConfig()`：对 `CODEX_CONFIG_PATH`（`~/.codex/config.toml`）调用 `shell.openPath`，成功返回 `{ ok: true }`；文件不存在时返回 `{ ok: false, error: '配置文件不存在: <路径>' }`，界面据此 toast 明确错误，不编造结果。
- 与既有的 `gptplus:codex:open`（打开目录）并列，spec.md 第 7 节 API 契约同步补上 `openCodexConfig`。
- 提示：若 Windows 尚未给 `.toml` 关联默认程序，首次点击会弹「你要如何打开这个文件」选择框，选定一次后以后直接打开。

## 验证

- 全量 Node 测试：246 项、0 项失败、1 项跳过（跳过项为真实 `config.toml` 处于注入状态的用例）。
- 新增用例：主页分体按钮——主按钮默认调用 `openCodexFolder`、小箭头展开二级菜单（`is-open`）、菜单恰有「打开文件夹 / 打开文件」两个条目、选择「打开配置文件」调用 `openCodexConfig` 且菜单收起；测试替身补 `document.removeEventListener`，mock api 补 `openCodexConfig`。
- 真实渲染层探针（隐藏窗口 + `capturePage` 裁剪截图）逐轮校正视觉：分体按钮拼合无缺口、菜单与按钮左右边缘坐标完全重合、顶栏无隐形空档、菜单条目文字无溢出（`scrollWidth == clientWidth`）。
