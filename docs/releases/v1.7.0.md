# gpt++ v1.7.0

## 软件内更新摘要

- 更新前实测安装目录能否写入：不可写时取消下载并说明原因，不再白下载完整安装包。
- 下载完成后再校验一次，权限不足时阻止重启安装，现有版本保持不变。
- Windows 安装器删除旧版本前先确认能在目标位置重建目录，失败即中止安装，不会把应用删空。
- 失败提示会给出具体被阻塞的目录，并提示改用管理员运行安装程序或可写目录。

## 详细说明

### 更新前检查安装目录

- 自动更新在用户点击下载更新后，先在安装目录的上级目录创建并删除一个探测目录，再在安装目录内写入并删除一个探测文件，据此判断安装器能否完成"删除旧版本再重建"的流程。
- 探测失败时不发起下载，设置页直接显示"安装目录不可写，更新已中止"以及被阻塞的具体路径，避免下载数十兆安装包后才在重启安装时失败。
- 安装包下载完成、准备退出并安装之前重复同样的检查；不可写时保留当前版本继续运行，不再进入重启安装。
- 探测自身异常（例如无法取得程序路径）时只记录日志并放行，不阻塞正常更新。非 Windows 平台不做该检查。

### 安装器保护现有安装

- NSIS 覆盖安装会先静默卸载旧版本，卸载器会删除整个安装目录，随后才由安装器重建并解压新文件。若安装目录的上级目录对当前用户只读，旧目录被删掉后无法重建，结果是应用文件消失，但注册表和快捷方式仍指向不存在的路径。
- 现在安装器在卸载旧版本之前的最后一个钩子里实测：安装目录已存在时，要求目录内可写文件、且上级目录可新建条目；安装目录不存在时，要求能实际创建出来。
- 任一项不满足即中止安装并提示以管理员身份运行安装程序，或选择当前用户可写的安装目录；此时旧版本文件、注册表和快捷方式都保持原样。
- 探测使用临时文件 `gptplus-install-probe.tmp` 与临时目录，写入成功后立即删除，不留下残留。

## 使用说明

- 如果设置页出现"安装目录不可写"的提示，说明 gpt++ 当前安装位置的上级目录没有普通用户写权限。可以用管理员身份运行官网下载的安装包重新安装一次，或把 gpt++ 安装到当前用户可写的目录，之后自动更新即可恢复正常。
- 本次发布沿用未签名 Windows x64 安装包，Windows 可能显示未知发布者或 SmartScreen 提示。

## 验证

- 全量 Node 测试：418 项，416 项通过、2 项按环境条件跳过，0 项失败。
- 新增 5 项更新器用例：上级目录只读、安装目录只读、目录缺失但可重建、非 Windows 放行、取消下载与阻止重启安装。
- 新增安装器脚本契约用例：写权限探测宏存在、探测路径正确、且挂载在卸载旧版本之前的钩子内。
- Windows x64 未签名安装包构建通过，NSIS 脚本编译无错误。
