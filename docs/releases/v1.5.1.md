# gpt++ v1.5.1

## 更新内容

### 新增：本地网关三协议互通

- 入站新增 `/v1/chat/completions` 与 `/v1/messages`，与原有 `/v1/responses` 并列；三种入站协议均可路由到 Responses、Chat Completions、Anthropic Messages 三类上游，支持 JSON 与 SSE 的 3×3 组合。
- 统一以 Responses item 作为内部中间表示，新增 `src/core/gateway/protocols.js`，集中处理协议归一化、Chat/Messages 响应与流式输出。
- 转换覆盖文本、图片、system/developer 约束、函数工具与工具结果、并行工具调用、reasoning/thinking 文本与签名、缓存 Token、`max_tokens` / 截断状态。
- Messages 入站支持 `x-api-key` 认证；错误按请求协议返回 Chat / Messages / Responses 对应结构。
- 对无法无损转换的音频、视频、文件及部分 Anthropic 服务端内置工具等输入明确返回 400，不静默丢弃字段。
- 上游拒绝推理档位时保留档位并只做一次兼容重试，不再删除 `reasoning_effort` / `output_config` 后伪装成功。

### 改进：推理、工具与用量统计

- 支持 DeepSeek `reasoning_text`、Anthropic thinking signature、`output_config.effort`、`prompt_cache_hit_tokens` / `prompt_cache_miss_tokens` 等字段。
- 修复工具名分片、Responses 增量收尾重复文本、两路工具参数串联等问题。
- 新增按单次请求统计的生成速度：以首段可见文本之后的耗时作为分母，排除思考等待；用量信息栏优先使用网关数据，读取不到时才回退到 rollout 事件。
- Chat 入站多候选 `n>1` 当前明确拒绝，避免只返回第一个候选造成静默截断。

### 修复：Codex 配置与界面

- 修复 gpt++ 重写 `~/.codex/config.toml` 时，把标记块内 ChatGPT 写入的 `[desktop]`、`model_reasoning_effort`、`[projects]` 等配置一起删除的问题。现在按 TOML 表边界只移除 `[model_providers.gptplus]` 及其子表；上下文窗口使用情况开关和推理强度不会因 gpt++ 修改配置并重启而被重置。
- 修复设置页对等共享客户端列表的语法错误。
- 修复微信扫码轮询在关闭/重新打开登录弹窗后的竞态，避免旧轮询覆盖新状态。
- 修复模型页对可空操作按钮的渲染，避免对空节点直接追加。

## 兼容性

- 现有提供商、API Key、注入状态、用量历史与对等共享配置无需迁移。
- 原有 `/v1/responses` 行为保持；新增的 `/v1/chat/completions`、`/v1/messages` 为增量接口。
- 跨协议转换仍不是所有厂商扩展字段的无损透传；不支持的内容类型会明确报错。
- 关闭注入时仍只还原 gpt++ 写入的顶层键和 `[model_providers.gptplus]` 段，其它配置原样保留。

## 验证

- 全量 Node 测试：336 项，335 通过，1 项按真实用户配置条件跳过，0 失败。
- 本地 E2E：21/21 通过；生成的模型目录可被当前 Codex CLI 解析并列出全部自定义模型。
- 本地 Windows x64 未签名安装包构建验证；GitHub Actions 会在标签推送后重新构建并创建 Release。
