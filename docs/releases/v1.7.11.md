# gpt++ v1.7.11

## 软件内更新摘要

- 修复开机自启动后插件偶尔没有注入 ChatGPT：启动后会确认调试端口可连，不可连时自动重启 ChatGPT 再注入。
- ChatGPT 自带的开机启动与“gpt++ + ChatGPT”同时开启时弹窗提示风险，可一键选择由谁负责启动。

## 详细说明

- 原因：ChatGPT 自带的开机启动任务会和 gpt++ 抢跑。ChatGPT 自己先启动时不带调试端口，gpt++ 带端口的启动请求被它的单实例机制吞掉，旧版只看到进程存在就记为成功，随后插件注入报 `ECONNREFUSED`。
- 开机拉起 ChatGPT 后必须连上调试端口才算成功；连不上且 ChatGPT 已在运行但没有调试端口时，结束它并带端口重新启动，最多尝试 3 次。启动命令超时或出错走同一套重试，全部失败时记录明确的失败日志。
- 新增冲突提示弹窗：选择“gpt++ + ChatGPT”开机自启动时，或 gpt++ 启动时已处于冲突状态，会说明风险并提供两个选项。“由 gpt++ 拉起 ChatGPT”会关闭 ChatGPT 自带的开机启动（等同于在任务管理器“启动应用”里禁用，可随时重新开启）；“由 ChatGPT 自己启动”会把 gpt++ 改为“仅 gpt++”，开机后的 ChatGPT 不带插件，需要在 gpt++ 里点“重启 ChatGPT”才会注入。也可以选择暂不处理，由自动重试兜底。
- 冲突检测只支持应用商店版（MSIX 安装）的 ChatGPT；被系统策略强制开启的启动任务无法在弹窗里关闭，对应选项会置灰并说明原因。
- 保留已有提供商、API Key、模型、插件配置和使用记录。

## 安装与升级

- Release 提供 Windows x64 NSIS 安装包、差分更新 blockmap 和自动更新元数据 `latest.yml`。
- 沿用项目现有未签名发行流程，安装器和主程序没有 Authenticode 签名。
- 自动检查仍只提示新版本，用户点击“立即更新”后才开始下载和安装。

## 验证

- 全量 Node 测试 530 项：527 项通过，2 项按本机配置条件跳过；1 项 NSIS 编译测试因构建目录缺少本地依赖未能运行，与本次改动无关。
- 新增开机抢跑重试、启动任务读取与关闭、IPC 和弹窗二选一交互的测试。
- 弹窗样式在浅色和深色主题下用真实样式表渲染检查；隔离数据目录的冒烟启动无报错。
- 关闭 ChatGPT 自带开机启动的真实注册表写入和开机重启后的整体效果未在发布前实机验证。
