# gpt++ v1.6.5

## 软件内更新摘要

- `/models` 新增模型默认启用，并默认开启推理。
- “新增”标记移到模型名右侧，模型页和提供商页不再错位。
- 更新弹窗和设置页显示最多 4 条精简摘要，并保留完整更新说明入口。
- 修复输入框用量状态栏的速度、缓存命中率和上下文三项显示为 `--`。

## 更新内容

### 改进：新模型默认启用并开启推理

- 从 `/models` 拉取到的新模型不再默认停用，也不再依赖上游是否正确返回推理能力字段。
- 新模型默认启用推理；已有模型的启用状态、推理设置和显示名称保持不变。

### 改进：新增标记移到模型名右侧

- 模型页的“新增”标记与模型名称同行，固定在名称右侧，不再占用推理列。
- 提供商编辑表单中的“新增”标记与模型 ID 同行，避免窄窗口和长名称下出现错位。

### 改进：更新时显示精简更新摘要

- 发现新版本后，从对应 GitHub Release 的 `## 软件内更新摘要` 读取最多 4 条要点。
- 更新确认弹窗和设置页的软件更新卡片展示同一组摘要，并提供“完整更新说明”入口。
- 摘要读取失败不会阻塞版本提示、下载或安装；旧 Release 缺少专用摘要章节时，会从“更新内容”等章节提取并排除兼容性、验证类内容。

### 修复：用量状态栏三项显示为 `--`

- 根因是同一会话存在多个 rollout 文件时，读取器先命中了没有 `token_count` 事件的主文件。
- 读取器现在会比较全部匹配文件，优先选择包含有效用量事件且时间最新的续接文件；空路径缓存会重新解析。
- 修复后，速度、缓存命中率和上下文窗口恢复为真实数值，仍只读取 `token_count` 元数据，不读取或暴露消息正文。

## 兼容性

- 提供商、API Key、模型、注入状态、用量历史和插件配置无需迁移。
- 更新检查仍然不会自动下载或安装，发现新版本后必须由用户确认。
- 新摘要接口失败时保留原有更新流程，不影响手动检查、下载和回退。

- 全量 Node 测试 355 项：354 项通过，1 项按真实 Codex 配置条件跳过，0 项失败；覆盖模型默认状态、新增标记布局、更新摘要提取、摘要失败降级、续接 rollout 文件选择和外部链接协议限制。
- 本地已成功构建 Windows x64 未签名 NSIS 安装器，并检查安装包、差分 `blockmap` 与 `latest.yml`。
