# gpt++ v1.2.6

## 更新内容

### 修复：Codex 多轮工具调用在严格中转上整轮失败

v1.2.5 修掉了工具 schema 的 `required: null`，但同一批请求还会撞上另外两个报错，且都在"助手先说一句、再调工具"的那一轮出现：

```
The `content[].thinking` in the thinking mode must be passed back to the API.
The `reasoning_content` in the thinking mode must be passed back to the API.
```

原因和 v1.2.5 是同一个根子：Codex 的一轮助手输出在 Responses 协议里是**三个独立条目**（`reasoning` + `message(文本)` + 若干 `function_call`），网关逐条 1:1 翻译成 chat 后，产生两处 OpenAI 直连能收、Anthropic 系上游不收的形状：

- 一轮助手被拆成**两条连续的 `assistant` 消息**（一条纯文本、一条只带 `tool_calls`），而 Anthropic 要求一个 assistant 轮只出现一次；
- `reasoning` 条目被整个丢弃，上一轮的思考文本没有回传，而开启 thinking 的上游要求原样回传。

修复（`src/core/gateway/adapters/openai.js`）：

- 新增 `mergeAssistantTurns()`：把连续的 assistant 消息合并成一条 `content + tool_calls`，这才是 chat 的标准形状；文本与思考都不丢。
- `reasoning` 不再丢弃，思考文本回挂到其后第一条 assistant 消息的 `reasoning_content` 上；多段思考按轮次归位，不串轮。
- 兼容重试（`compat`）时剥掉 `reasoning_content`：不认这个字段的上游会报 `Unknown parameter`，重发时不带它。原有的兼容重试判据不会误伤本次的回挂（`must be passed back` 不触发重发）。

### 为什么有时能用有时不能用

这家中转后面挂了严格程度不同的后端，同一份报文在不同时间窗口的结果不一样：本机日志里 08:44 稳定 400 的报文，09:14 起被连续放行 11 次。本次修复让报文在严格和宽松两种校验下都合法，不再依赖上游当天用哪个后端。

## 影响范围

只影响 `api=openai` 的协议转换通道。用 23 个真实 Codex 会话逐条比对 v1.2.5 与本次代码：

```
responses 透传 payload 与上一版完全一致: 23/23   <= 原生 Responses 提供商零影响
anthropic 消息转换与上一版完全一致:     23/23   <= 未改动
toMessages 有差异: 16；可由「合并 + 回挂思考」完全解释: 16；无法解释: 0
```

`api=responses` 的适配器是逐字节透传（只改写 model），不经过本次改动的任何函数。

### 已知代价与边界

- 回挂思考文本会让 prompt 变长，按上下文计费/预扣的中转会更贵——这是严格上游的必要条件，不是可选项。
- `api=anthropic` 通道本次未改动。若以后直连 Anthropic 官方，thinking 块需要携带原始 `signature`，仅靠 summary 文本无法还原，届时需要单独处理。

## 验证

- 全量 Node 测试：235 项、0 项失败、1 项跳过（真实 `config.toml` 处于注入状态）。
- 新增用例：连续 assistant 合并（正序/反序/跨角色不合并）、思考按轮回挂、无后续条目的 reasoning 安全丢弃、compat 剥字段。
- 真实上游端到端：修复前 100% 400 的会话历史，修复后连打 3 次 200；16 个真实 dp 会话批量重放，schema 与 thinking 类 400 全部消失（剩余失败为中转账户余额不足，非协议问题）。

## 安装与升级

- Release 提供 Windows x64 NSIS 安装器、差分更新 blockmap 和自动更新元数据 `latest.yml`。
- 沿用仓库现有未签名构建流程，Windows 可能显示"未知发布者"或 SmartScreen 提示。
- 升级不清空用户配置、提供商、API Key 或历史使用量数据。
- 已安装的 gpt++ 会在启动约 8 秒后检查 GitHub Release，发现新版本仅弹窗提示，不会自动下载。
